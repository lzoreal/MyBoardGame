## 覆盖率的统计方式

测试统一用 `vm.runInThisContext(..., { filename: 'cabin.js' })` 加载引擎，避免 `eval(fs.readFileSync())` 让 V8 看不到脚本。

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File tools/run-cabin-coverage.ps1
```

脚本会：

1. 用 `NODE_V8_COVERAGE=.covall` 跑全部 13 组测试；
2. 把 `.covall` 中 basename 为 `cabin.js` / `cabin-packs.js` 的脚本 URL 统一为绝对 `file:///D:/MyBoardGame/js/games/...`；
3. 调用 `c8 report` 合并，输出 `coverage-report.txt` 和 `coverage/coverage-final.json`。

## 本轮补齐的行为路径

- `#4` `gain_curse`：首次获得诅咒知识；同房间第二次转交给缺标记英雄。
- `#4` `prepare_ward`：成功档获得守护结界。
- `#14` `cast_spell` 失败档：`lose { trait: 'sanity' }` 实际推进神智轨道。
- `#47` 已修复 `knowledge` 属性别名，失败档 `gain` 正确推进 `known` 轨道。
- 武器评分：攻击时 `pickWeapon` 按 `attackDice * 4 + attackResult` 选最高分武器。
- 暗女王：第五片精灵之火触发降临，并解析降临房间。
- 房子：只在 ON 发电机同房间或相邻板块攻击英雄。
- `armor_spell_broken`：自定义目标标记读取。
- `lowestMight`：按力量最低选叛徒。
- `rideElevator`、`pct`、`moveTrack`、`rollDamage`、`inLineOfSight`、`hasDistanceWeapon` 的纯函数边界。

## 仍然没有覆盖的分支

`cabin.js` 还有 **714 个分支计数为 0**，主要集中在：

1. 怪物攻击的伤害分配、死亡、多人目标、跨层寻路和移动点不足。
2. 探索的非法门、封死楼层回退、闹鬼后多人同房加费。
3. 交易拒绝、撤回、索引变化。
4. 事件、物品、预兆、房间的组合边界。
5. 50 个剧本的失败路径和 3–6 人差异。

这些分支不是“函数没执行”，而是“同一函数内的条件组合没有走到”。这正是下一轮分支矩阵测试的目标。

## 当前判断

这版可以标记为：

- 每个引擎函数至少执行一次（100%）；
- 13 组测试、1918 条断言、60 条实机动作回归全部通过；
- 全项目语句覆盖 99.23%，`cabin.js` 语句覆盖 97.15%；
- 50 个官方剧本都有 Setup / 目标 / 行动层测试入口。

但仍不能标记为“3E 规则完整”：
- 分支覆盖率 75.19%，仍有 714 个分支是防御性错误组合、稀有剧本组合或非法输入；
- `custom` 目标仍依赖剧本数据入口；
- 部分房间、物品、怪物特殊能力只验证了主路径。

下一轮应优先做分支矩阵和失败路径，而不是继续增加 Setup 字段断言。
